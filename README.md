# Text Popup

把笔记里**可放大的区块**单独放大到弹窗里阅读，交互与 Obsidian 内置的图片放大（lightbox）一致。

可放大的区块有八类：手写的**块级 HTML**、**围栏代码块**、**标注（Callout）**、**`$$` 数学块**、**图片**、**引用块（`> …`）**、**表格**、**Canvas 白板**。除手写 HTML 外都是原生内容、不需要任何额外标记；其中四类（代码块 / Callout / 数学块 / 图片）本身就有右上角的控制图标，本插件把放大图标加进那条图标里（位于 `</>`「编辑这个模块」的左侧；图片则在原生「放大」图标左侧），引用块没有原生控制图标，图标由本插件自己画在块的右上角，表格与 Canvas 的图标容器也由本插件自己建（Obsidian 不给它们控制图标）。

## 用法

### 手写的块级 HTML

在笔记中用块级 HTML 标签把想放大的内容包起来：

```html
<div>
这是要放大的第一行
这是要放大的第二行
</div>
```

在**实时预览**中把鼠标移到这个块上，右上角会出现两个图标：左边是本插件的**放大图标**（双箭头），右边是 Obsidian 自带的「编辑这个模块」（`</>`）。点击左边的放大图标，弹窗即显示该块内的文字。

- 用 `Esc`、点击弹窗外的遮罩、或点击弹窗右上角的关闭按钮都可以关闭。
- 弹窗**铺满整个 Obsidian 窗口**（与内置图片放大同一尺寸基准），适合演示笔记时把重点单独凸显出来。
- 弹窗**标题栏显示来源笔记名**，便于演示时溯源；笔记名固定使用主题文字色，不受设置里的「弹窗文字颜色」影响。同一个笔记里有多个可放大区块时，标题栏还会附带**「当前 / 总数」序号**（例如 `我的笔记 · 2 / 5`）；只有一个时**不加序号**，与 1.0.2 的标题完全一致。
- 打开后可用 **`←` / `→` 在同一个笔记的全部可放大区块之间切换**（八类区块混在一起、按文档顺序），不用关掉弹窗再去找下一个图标。规则与 Obsidian 内置的图片放大（lightbox）一致：只用左右两个键；在最后一个按 `→` 环绕回第一个，在第一个按 `←` 环绕到最后一个；**空块**（点了不会弹窗的块）不参与切换。切换后正文会**回到顶部**，而已调整的**字号 / 缩放会保持**，方便连续阅读；`Alt`+点击的**视图缩放则会复位**（它的锚点属于上一块内容）。
- 弹窗底部有控制条，可临时调整**字号**与**缩放**，以及一键**恢复默认**。文字在窗口里自动居中；内容超出窗口时在弹窗内滚动。
- 弹窗里默认**按语法渲染块内的 HTML 与 Markdown**：`<b>`、`<span style>`、`<table>`、`<img>` 等标签按语义显示，块内的 `**粗体**`、`# 标题`、`- 列表`、`> 引用`、`| 表格 |`、`` `行内代码` `` 都会正常渲染；`[[笔记]]` 可点击跳转，`![[图片]]` 与 `![](图.png)` 能显示出图。
- 弹窗内的排版复用 Obsidian 阅读视图的样式（内容容器带 `markdown-rendered` 类），因此观感与阅读视图一致，标题、列表等会随字号 / 缩放等比放大。
- 按住 **`Alt`（macOS 上是 `Option`）点击正文**，会把内容**放大到 2 倍**，并把**点击处移到画布中间**（点击处离文档边缘太近、滚动范围不够时尽量居中）—— 与 reveal.js 的缩放插件同一手感；再按住 `Alt` 点一下即**还原**，并回到放大前看到的滚动位置。放大 / 还原都走一段 **500ms 的过渡**（缓动 + 逐帧插值），不是瞬间跳变：被点中的那处会**沿直线**滑到画布中心，中途再点一下就从当前状态接着走，不会跳一下重来。系统开了「减少动态效果」时过渡自动跳过，直接给结果。放大后（不放大时也能用：宽表格、宽图片放不下时同样管用）**按住空格拖拽**可平移画布，**焦点落在底部控制条按钮上也照常生效**。这两个手势只作用于正文区，不影响底部控制条，正文里的 `[[链接]]` 也不会因为 `Alt`+点击而跳转；图片同样吃这个放大（底部控制条的「字号 / 缩放」对图片则仍然无效）。控制条的「恢复默认」会把字号、缩放与视图缩放一起复原。代价是**空格不再激活控制条按钮**（`Enter` 照旧可以）：弹窗打开时焦点本就由核心自动落在第一个按钮上，把空格留给平移是唯一能让手势稳定的做法。
- 按住 **`Ctrl`（macOS 上是 `Command`）滚动鼠标滚轮**（或触控板双指缩放）可**以指针处为锚**缩放视图，手感与 Obsidian 内置的**图片查看器**一致：倍数区间 **1× ~ 10×**，每格约 ±0.67（触控板更细，靠连续帧累加）；缩放**瞬时生效**、没有过渡，连续滚动不会被反复打断；缩回 **1×** 即回到「一屏装下」的原位。**放大后不按修饰键直接滚轮就是平移**（内容变大了，弹窗本来就滚得动），按住空格拖拽也照旧可用。图片、Canvas、Excalidraw 嵌入都吃这个手势（它们与文字走同一套视图缩放）。

### 代码块 / Callout / 数学块

这三类是 Obsidian 原生区块，**不需要任何额外标记**，按平时写法写出来就有放大图标：

````markdown
```typescript
const answer = 42;
```

> [!NOTE] 标题
> Callout 的正文

$$ a+b = c $$
````

在**实时预览**中把鼠标移到它们上面，右上角就会出现本插件的放大图标。图标长在哪个位置取决于区块类型：

- **Callout / 数学块** → 出现**两个**图标：左边是本插件的放大图标，右边是 Obsidian 自带的「编辑这个模块」（`</>`）。
- **代码块** → 放大图标在右上角的**语言名 / 复制 chip 里**（也就是 ```` ```typescript ```` 那个 chip），是 chip 里的第二个图标；只有语言被 `mermaid` / `base` 这类处理器接管时，才会像上面那样出现在 `</>` 左侧（此时这块由处理器渲染成图 / 数据库视图，不再是普通代码块）。

弹窗里的显示效果与编辑器所见一致：

- **代码块** → 带语法高亮与核心复制按钮的代码块；
- **Callout** → 真正的 Callout（类型图标 + 标题 + 正文）；
- **数学块** → 排版好的公式（首次打开需要动态加载 MathJax，可能会多等一下）。

三类各自有开关（见下方「设置项」），关掉后该类的图标会立刻消失、也不再计入方向键的候选总数。

### 引用块

Markdown 的引用块（`> …`）同样是原生内容，**不需要任何额外标记**：

```markdown
> 君子曰：“大德不官，大道不器，大信不约，大时不齐。”
> 三王之祭川也，皆先河而后海。
```

在**实时预览**中把鼠标移到引用块的任意一行上，块的**右上角**就会出现本插件的放大图标（与核心给代码块 / 图片的图标同一套胶囊皮肤、同一套定位，只是它由本插件自己画上去）。点它打开弹窗，正文是**带引用条的渲染结果**（`MarkdownRenderer` 渲染出的 `<blockquote>`），不是字面的 `>`。

几条与写法有关的规则：

- **整段算一条**：连续的 `>` 行（含引用里的标题、列表、围栏、嵌套 `> >`）合成一条候选，一个引用块只有一个图标。
- **只有 `> ` 的空引用行**（连在引用段尾部）不产候选、也不挂图标 —— 点开只会是一屏空白。它仍算进区间，只是不成条。
- **懒惰续行不算进区间**：`> a` 的下一行不写 `>` 时，Obsidian 仍把它画在引用条里，但本实现按 `>` 前缀断句（与 Callout 同一取舍），弹窗里会少显示那一行。
- **引用行里的图片**不单独成条，由外层引用块这一条覆盖（进去照样能看到图）—— 与「Callout 内的图片不单独成条」同一口径。
- **引用块里的围栏**（行首 `>` 后接三反引号）不另算代码块、也不挂代码块 chip 的图标，整段只有引用块那一个图标。

引用块有单独开关（见下方「设置项」的「放大引用块」），关掉后图标会立刻消失、也不再计入方向键的候选总数。

> 与另外六类的差别：其余几类的图标都插在**核心已经建好的**容器 / chip 里（表格那处的容器也是本插件自己建的，见下方「表格」），引用块连容器都没有 —— 它的图标由一个 CodeMirror 装饰器承载（实现细节见「实现要点」）。

### 表格

Markdown 表格（`| a | b |` + 分隔行）同样是原生内容，**不需要任何额外标记**：

```markdown
| 中文 | 词 | 例句 |
| ---- | ---- | ---- |
| 我的 | mine | The dog is mine. |
```

在**实时预览**中把鼠标移到表格上，表格**右上角**就会出现本插件的放大图标（与核心给代码块 / 图片的图标同一套胶囊皮肤、同一套定位）。点它打开弹窗，正文是**真正的表格**（`MarkdownRenderer` 渲染出的 `<table>`，有表头与边框），单元格字号也跟随弹窗的「字号 / 缩放」。

表格的图标与另外几类有一处不同，值得单独说明：

- **图标容器是本插件自己建的**。Obsidian 给表格 widget 建的容器（`.cm-table-widget`）里**没有** `.embed-actions` —— 核心的「编辑这个模块」图标只给嵌入笔记 / 代码块 / 数学块 / HTML 块建，不给表格建。所以本插件在表格本体（`.table-wrapper`）里自己建一个同形容器再插按钮：位置、尺寸、悬停皮肤全部复用核心那套，只是「悬停显形」这条要自己补（核心的显隐规则里显式写明了 `:not(.cm-table-widget, …)`）。
- **表格表头行必须顶格**（行首不能有空格）：实时预览只给顶格的表头行建表格 widget。带前导空格的写法（含「`- item` + 空行 + 2 空格缩进的表」，那两行在编辑器里只是列表项里的普通文字）既不产候选、也没有图标，两边一致。
- **只在表格本体（而不是整个块容器）上定位**：表格 widget 的容器常被拉满整行宽，锚在它上面图标会飘到编辑区右缘、离表格很远；锚在表格本体右上角则始终贴着表格。
- **表格右上角那枚图标会盖住表头最后一格的右上角约 28×24 px**（未悬停时透明但占位）—— 与引用块图标那条限制同性质。它不重叠核心自己的「+ 列」按钮（在表格右缘**外侧**）与列拖拽手柄（在表头上方）。
- **表格改动会重建 DOM**：在单元格里改字是原地更新（图标不动），但**插入 / 删除行列**等结构化改动会让核心重建表格 DOM，图标先消失、随即被重扫补回（150 ms 防抖内）。

表格有单独开关（见下方「设置项」的「放大表格」），关掉后图标会立刻消失、也不再计入方向键的候选总数。

### 图片

图片同样是 Obsidian 原生内容，**不需要任何额外标记**，按平时写法写出来就有放大图标：

```markdown
![说明文字](图片.png)

![[图片.png]]
```

在**实时预览**中把鼠标移到图片上，右上角会出现**三个**图标，从左到右依次是：

1. **本插件的放大图标**（双箭头）—— 用本插件的弹窗显示这张图；
2. Obsidian 自带的**放大**（放大镜）—— 仍是 Obsidian 自己的图片查看器，本插件不碰它；
3. Obsidian 自带的**编辑这个模块**（`</>`）。

两个放大图标是**兄弟节点**、各自独立：点原生那个走 Obsidian 的方式，点本插件那个走弹窗，互不干扰。本插件的图标插在原生「放大」的**左侧**，与 `.embed-actions` 里其它区块「本插件图标在最左」的排列保持一致。

弹窗里的图片**按 Obsidian 阅读视图的方式显示**（同样交给核心的 `MarkdownRenderer` 渲染），并计入方向键的候选总数 —— 可以像其它区块一样用 `←` / `→` 在「代码块 / Callout / 数学块 / HTML 块 / 图片 / 引用块 / 表格 / Canvas」之间连续翻。

弹窗里图片的**尺寸口径与 Obsidian 自带的图片放大（lightbox）一致**，两条都是一样的：

- **按可用高度整体装下**：宽高双约束、等比缩放，一张图不会高过一屏、也不会在弹窗里出现滚动条；小图**不放大**（仍按自然尺寸居中）。唯一差别是核心会给图片四周留 8px 内边距、弹窗不留，所以同一张图在弹窗里会略大一点点。
- **忽略尺寸语法**：`![x](a.png)` 与 `![x|300](a.png)`、`![x|600x200](a.png)`、`![[a.png|200]]` 在弹窗里渲染结果完全相同（核心的图片放大也一样：它在源头就不带尺寸）。也就是说尺寸语法只在笔记里（编辑器 / 阅读视图）生效，弹窗里一律按原图比例显示。
- 这条口径的**粒度是「弹窗里出现的每一个 `<img>`」**：Callout / 表格 / 引用块 / HTML 块**内部**的图同样按弹窗的可用高度收缩，不只是「单独一张图」的条目。

支持的写法与位置：

| 写法 | 是否支持 |
| --- | --- |
| `![说明文字](图.png)`、`![说明文字\|120](图.png)` | ✅ 独立行、列表行（`- `）都支持 |
| `![[图.png]]`、`![[图.png\|100]]`、`![[图.png\|图注]]` | ✅ 同上 |
| `![x](https://…/a.png)` 外链图片 | ✅ 外链不看扩展名 |
| **引用行**（`> ![x](p.png)`）里的图片 | ❌ 由外层**引用块**这一条覆盖（进去照样能看到图，见「引用块」）；那个引用行上的图标是引用块的放大图标，不是图片的 |
| `<span>` 一类**行内 HTML 包裹**的图片 | ❌ 这类图片没有原生图标条，不单独成条 |
| **行内代码**（`` `![x](p.png)` ``、`` `![[图.png]]` ``）里的图片 | ❌ 在实时预览里它只是一段文字（`span.cm-inline-code`），没有原生图标条，因此不单独成条 |
| **Callout 内**的图片 | ❌ 由外层 Callout 这一条覆盖（进去照样能看到图） |
| **表格单元格**里的图片 | ❌ 实测它们没有原生图标条，不单独成条 |
| **缩进代码块里**的图片（顶格 4 空格、或相对所在列表项多出 4 列） | ❌ 实测没有原生图标条，不单独成条（列表项内的 4 空格是**正常嵌套**，照样支持 —— 见「已知限制 → 缩进怎么算」） |
| **嵌入笔记**（`![[某笔记]]`）里的图片 | ❌ 候选集来自外层笔记文本，在那里点开也定位不到，因此不注入图标 |
| `![[x.pdf]]` / `![[x.mp4]]` 等非图片嵌入 | ❌ 不在本次范围 |

图片有单独开关（见下方「设置项」的「放大图片」），关掉后图片上的图标会立刻消失、也不再计入方向键的候选总数。

### Canvas 白板

`![[白板.canvas]]` 同样是原生内容，**不需要额外标记**：鼠标移到嵌入上，右上角会出现本插件的放大图标（Canvas 没有原生控制图标，那个容器由本插件自己建）。

弹窗里显示的是**只读快照**，而不是 Obsidian 给嵌入画的那张缩略图（核心的嵌入是一张 `svg.canvas-minimap`：只有轮廓、没有文字、没有交互，放大它等于放大一张缩略图）。快照按画布坐标 1:1 画出：

- **文字节点**的 Markdown（节点里的 `**粗体**`、`[[链接]]`、`![[图片]]`、`$公式$` 都按笔记里的样子渲染）、**文件节点**（`![[文件]]`，笔记 / 图片都出）、**外链节点**（可点击）、**组**（背景色块 + 标题）、**连线**（按 `fromSide` / `toSide` 锚点，`toEnd` 为 `none` 时不画箭头），节点的颜色（`1`–`6` 或十六进制）与笔记里的画布一致；
- **一屏装下**：快照整体等比缩到弹窗内容区里（**只缩不放**，小画布按原尺寸居中），放大仍然用弹窗既有那两条手势（`Ctrl`/`Command`+滚轮、`Alt`+点击）。因为画出来的是矢量 DOM，放大后文字依旧清晰；节点文字**固定 16px**、不跟随弹窗字号（节点盒的宽高来自画布 JSON，字号一变文字就会被裁掉）；
- **缩小的笔记卡片也只出那一节**：卡片在画布里用「缩小至标题…」/「缩小至块…」后，弹窗里同样是那一节（`.base` 卡片的「固定视图…」、PDF 卡片的 `#page=N` 同理）—— 画布 JSON 里的 `subpath` 会拼进那条内嵌链接，交给核心同一套 embed 管线去切，本插件不自己解析 Markdown；subpath 解析不到（标题改名 / 块 id 被删）时退回整篇，与核心画布一致；
- **完全没有写回路径**：快照只是本插件自建的 DOM，拖拽节点、双击文字都不会改动 `.canvas` 文件，也没有选中 / 编辑 / 缩放画布本体这些能力（见「已知限制 → Canvas 的边界」）。

关掉设置里的「放大 Canvas」后，笔记里的画布图标立刻消失、也不再计入方向键的候选总数（与表格那一条同法）；关掉「渲染 HTML 与 Markdown」时，画布显示文件名而不是空白。

### 命令与右键菜单：把普通 Markdown 转成可放大的块

不想手写 HTML 标签时，选中一段普通 Markdown 文本，用两个命令直接转换。**命令面板**与**编辑器右键菜单**里都有这两项（没有选区时命令不可用，右键菜单里也不出现）：

| 命令 | 作用 |
| --- | --- |
| `Popup Selected Text` | 把选中的 Markdown 包成一个块（单行选区用「单行文本包裹标签」，默认 `p`；含换行时用「多行文本包裹标签」，默认 `div`），实时预览里立刻出现放大图标 |
| `Unpopup Selected Text` | 反向操作：去掉最外层标签，并把块内的 HTML 还原成 Markdown |

`Popup Selected Text` 的**行内**转换规则：

| 选区里的写法 | 转成 |
| --- | --- |
| `**粗体**` `__粗体__` | `<strong>粗体</strong>` |
| `*斜体*` `_斜体_` | `<em>斜体</em>` |
| `==高亮==` | `<mark>高亮</mark>` |
| `~~删除线~~` | `<del>删除线</del>` |
| `` `行内代码` `` | `<code>行内代码</code>` |
| 已经写好的 HTML 标签（如 `<span style>`） | 原样保留 |

**列表**、**表格**与**标题**会被转成真正的块级元素（这三类留原文时都会出问题，见下面的「为什么要转」）。

先看**列表**（无序 / 有序 / 任务列表都认，缩进支持的嵌套层数不限）：

| 选区里的写法 | 转成 |
| --- | --- |
| `- a` `* a` `+ a` | `<ul><li>a</li></ul>` |
| `1. a` `1) a` | `<ol><li>a</li></ol>`；首项编号不是 1 时带 `start`，例如 `3. a` → `<ol start="3">` |
| `- [ ] a` `- [x] b` | `<ul class="contains-task-list">`，每个任务项是 `<li class="task-list-item">` + `<input class="task-list-item-checkbox" type="checkbox" disabled>`，勾选项多一个 `checked` |
| 缩进更深的 `  - b` | 嵌套的 `<ul>` / `<ol>`（反向还原时每层补 2 空格缩进） |
| 项里的 `**粗体**`、`==高亮==`、`` `代码` `` | 走**同一套**行内转换，上面那张表照旧适用 |

再看**表格**（GFM 表格；表头行 + 分隔行 + 数据行）：

| 选区里的写法 | 转成 |
| --- | --- |
| `\| a \| b \|` + `\| - \| - \|` | `<table><thead><tr><th>a</th><th>b</th></tr></thead></table>` |
| 再有数据行 `\| 1 \| 2 \|` | 追加 `<tbody><tr><td>1</td><td>2</td></tr></tbody>` |
| `\| :--- \| ---: \| :---: \|` | 该列带 `align="left"` / `align="right"` / `align="center"`（表头与数据行的单元格都带） |
| 格里的 `**粗体**`、`` `代码` `` | 走**同一套**行内转换，上面那张表照旧适用 |
| 格里的 `\|`（反斜杠 + 竖线） | 转成字面竖线（表格不会被自己格内的竖线切断） |

判定与 Obsidian 保持一致（少转一格也不多转一格）：

- **表格必须「起一个块」**：表头行前面得是空行（或选区开头）。`text` 紧邻表头时不成表格，只是一段带竖线的普通文字 —— 反向还原时会自动补上这个空行，所以往返稳定。
- **表头行与分隔行都必须含 `|`**：`a` + `---`、以及 `| a |` + `---` 都会被 Obsidian 渲染成 **Setext 标题**（阅读视图里是 `h2`，不是表格）。单列表格要写 `| a |` + `| - |`。
- **列数取分隔行**：表头行与数据行按它截断 / 补空，所以「表头 2 格 + 分隔行 1 格」是一张单列表格。
- **首尾竖线可省、横线数量不限**：`a | b` + `--- | ---`、`| a | b |` + `| - | - |` 都是表格。
- **数据行的终止条件**：空行、缩进 ≥4 空格、不含 `|` 的行、列表行、`>` 引用行、`#` 标题行。表格**后面**不需要空行（下一行直接是独立段落）。两个分隔行不会「开第二张表」，表中间长得像分隔行的那一行只是普通数据行。
- **表格先于列表判定**：`- a | b` + `--- | ---` 是表格（与 Markdown 的块规则顺序一致）。

最后看**标题**（ATX 标题，1–6 个 `#`）：

| 选区里的写法 | 转成 |
| --- | --- |
| `## 标题` | `<h2>标题</h2>` |
| `# H` … `###### H` | `<h1>H</h1>` … `<h6>H</h6>`（按 `#` 的个数分级） |
| `## T ##` / `## T ###` | `<h2>T</h2>`（尾部闭合串去掉） |
| `#⇥T` / `#     T` | `<h1>T</h1>`（标记后的分隔空白归一） |
| `#` / `###` | `<h1></h1>` / `<h3></h3>`（空标题合法） |
| 标题文字里的 `**粗体**`、`` `代码` `` | 走**同一套**行内转换，上面那张表照旧适用 |
| 标题行下面的正文行 | 照常转换，**落在标题元素外面**（`<h2>标题</h2><br>正文`） |

判定与 Obsidian 保持一致（少转一格也不多转一格）：

- **缩进 0–3 个空格**：` # T`、`   ### T` 是标题；缩进 4 个空格或含 Tab 是缩进代码块，不转。
- **`#` 后面必须是空白或行尾**：`#nospace` 不是标题；7 个 `#`（`####### x`）也不是标题；`\# x`（反斜杠转义）同样不转。
- **尾部闭合串**必须是「空白 + 纯 `#`」：`# T #` 转成 `T`，而 `# T #extra` 是标题「T #extra」、`# T#` 是「T#」、`# T \#` 是「T \#」（那个 `#` 被转义，不算闭合串）。
- **标题先于表格判定**：`# x | y` + `| - | - |` 里第一行是**标题**（核心的实测结论），不是表格。
- **表格可以紧跟在标题后面**：`## T` 的下一行直接写表头行（无空行）照常成表格 —— 标题不会「懒惰续行」把表头行吃掉。这是相对 1.0.9 及之前**放宽的一条表格前置条件**，其余前置条件（段落 / 列表行 / 引用行后面不成表格）不变。
- **列表项里、引用行里的标题不处理**：`- # T` 里的 `#` 保持字面（列表项内容按行内走，是既有边界）；`> #### T` 留给原文（弹窗里 `>` 会被序列化成 `&gt;`，本来就不会变成引用）。
- **Setext 标题（`S` + `===` / `---`）本次不转**：往返必然变形，且 `===` / `---` 与分隔线、表格分隔行共享字符。`S` + `===` 在弹窗里落在一个段落里（`===` 是字面文本），所以「不转」的代价只是形态没升级、内容不会被吞。

为什么要转：Obsidian 的**编辑器**不解析 HTML 块里的 Markdown，`**粗体**` 在块里会原样显示成星号。`[[笔记]]`、`[文字](链接)`、`![[图片]]`、`$公式$` 与 `> ` **引用**有意不转：留原文时弹窗里反而能点、能出图、能渲染（编辑器里则仍显示符号）。

**列表、表格与标题是三类例外**，因为「行首 + 换行」这些条件是它们成立的前提，而生成结果把正文压成了一行 —— 留原文就会出问题（编辑器里不解析、弹窗里也认不出）：

- `- a<br>- b` 不会变成列表；
- `| a |<br>| - |` 不会变成表格（弹窗的判据是「表头行的**下一行**是分隔行」，被压成一行后这个条件不再成立）；
- `## T<br>正文` 会**把后文变成标题**：`##` 的作用范围是「到本行结束」，而 `<br>` 只是行内元素、不结束标题 —— 弹窗里于是只剩一个 `<h2>`，标题文字里被塞进了整段后文（`data-heading` 属性里就能看到 `<br>` 与后文）。

所以这三类必须转成真正的 HTML 元素。其余「留原文还能在弹窗里渲染」的写法（链接、图片、公式、引用）一概不动。注意标题与引用这两类过去在文档里被放在一起（都算「块级 Markdown，有意不转」），现在**只有引用留原文** —— 标题独占一行时留原文确实能渲染，但多行选区里它后面必然还跟着内容。

外层标签按选区**有没有换行**分流：单行选区用「单行文本包裹标签」（默认 `p`），含换行时用「多行文本包裹标签」（默认 `div`）；正文含块级元素（列表 / 标题）时一律按多行处理（原因见下）：

```html
<!-- 单行选区：正文就是一行，不需要 <br>，所以默认用 p -->
<p>
只有一行
</p>
```

```html
<!-- 多行选区：正文压在一行、用 <br> 表达换行，原文的一个空行 = 相邻两个 <br> -->
<div>
第一行<br>第二行<br><br>第二行之后是一个空行
</div>
```

列表元素同样压在正文那一行里，块内依然没有空行：

```html
<div>
文字<br><ul><li>第一项</li><li>第二项</li></ul><br>文字
</div>
```

表格也一样压在正文那一行里（表格必须「起一个块」，前面的 `text` 与它之间用两个 `<br>` 表达那个空行）：

```html
<div>
文字<br><br><table><thead><tr><th>第一列</th><th>第二列</th></tr></thead><tbody><tr><td>一</td><td>二</td></tr></tbody></table>
</div>
```

标题也压在正文那一行里，**后文留在标题元素外面**（这是这个功能要解决的问题：`##` 留在原文里会连后文一起吃掉）：

```html
<div>
<h2>标题</h2><br>正文
</div>
```

选区**只有一行**、但正文里含块级元素时（例如只选中 `- a` 或 `## 标题` 这一行），也会改用「多行文本包裹标签」：`<ul>` / `<hN>` 会把未闭合的 `<p>` 顶开、解析器还会补出一个空 `<p>`，那样生成的块**没有放大图标**（点它的图标会翻出别的条目，即「幽灵块」）。所以「正文里有块级元素」按多行形态处理，与「选两行」的结果形态一致。表格不需要这条特判 —— 它天然 ≥2 行（表头行 + 分隔行），按「有没有换行」本来就会走多行标签；`<table>` 也不会把 `<p>` 顶开（实测 `<p><table>` 在弹窗里照常出表格）。

这样既保证块里没有空行（HTML 块到第一个空行就结束），也让弹窗里的换行 / 空行与原文完全一致。`Unpopup Selected Text` 只认块最外层的标签，**块后面紧邻的文字不会被吃掉**；块内不认识的标签一律原样保留、不做修复。

列表的反向还原：`<ul>` / `<ol>` / `<li>`（含任务复选框）还原成 `- ` / `1. ` / `- [x] `，嵌套列表每层补 2 空格缩进；畸形列表（没有 `<li>`、缺闭合标签、嵌套不闭合）整段原样保留。

表格的反向还原：`<table>` 还原成表头行 + `| --- |` 分隔行 + 数据行。第一行一律当表头（Markdown 表格必须有表头，HTML 没有这个概念，没有 `<thead>` 也认）；对齐从**表头行**逐列读 `align`；表格前面会补够空行（表格必须「起一个块」，否则还原出来的东西不成表格）；单元格里的字面竖线补回反斜杠。

**表达不了就整段原样保留**（与畸形列表同待遇，不猜、不降级、不丢信息）：单元格带 `colspan` / `rowspan`（≠1）或 `style`、单元格内容含换行（`<br>`、嵌套列表、嵌套表格）、格数与表头行不一致（Markdown 表格必须矩形）、没有 `<tr>`、缺 `</table>`、表格里夹着 `<div>` 一类别的元素。

标题的反向还原：`<h1>`–`<h6>` 还原成对应数量的 `#`（空标题只输出 `#`×N，不留尾空格），标题文字走同一套行内还原；标题前面**只需要一个换行**（ATX 标题能打断段落，也能紧跟列表 / 表格后面，这一点与表格「必须补整行空行」不同）。同样**表达不了就整段原样保留**：开标签带属性（`class` / `style` / `id`…，ATX 表达不了）、找不到 `</hN>`、内容还原后含换行（`<h2>a<br>b</h2>` —— Markdown 标题不能跨行）。

以下几条是**有意的归一化**（与既有的 `<b>` → `**` 同性质，往返因此不保证逐字节相同）：

1. 无序标记 `*` / `+` 归一成 `-`，有序标记 `1)` 归一成 `1.`，任务项 `[X]` 归一成 `[x]`；
2. 有序列表只保留首项编号：`1. a` + `5. b` 往返后是 `1. a` + `2. b`（HTML 的 `<ol>` 本来就不保存中间编号）；
3. 选区首行的缩进会被去掉：`  - a` 还原成 `- a`（HTML 里块内的前导缩进没有语义）；
4. 表格的单元格两侧空白被去掉、分隔行的横线统一成 3 个、表头与数据行的多余单元格按列数截断：`a | b` + `--- | ---` 往返后是 `| a | b |` + `| --- | --- |`；
5. 表格单元格里转义的竖线会被规范化（`\|` ⇄ 字面 `|`）：往返一致，但「本来就是表格的文本」过一次转换后不是逐字节相同；
6. 标题的尾部闭合串不保留、标记后的分隔空白归一成一个空格、前导缩进去掉：`## T ##` → `## T`、`#⇥T` → `# T`、`   ## T` → `## T`；
7. 标题里的行内转义写法不解析也不还原（与既有行为一致）：`# T \#` → `<h1>T \#</h1>` → `# T \#`（那个反斜杠原样留着）。

### 命令：直接打开当前笔记的第一个 Popup

笔记里已经标好块之后，想看时不必先找到其中一个、再把鼠标移到它上面 —— 用**命令面板**里的 `Show Popup In The Note`（中文界面下是「打开当前笔记的第一个 Popup」）就能直接打开**当前笔记里的第一个可放大区块**：

| 命令 | 作用 |
| --- | --- |
| `Show Popup In The Note` | 打开当前笔记里的第一个可放大区块；打开后照旧可以用 `←` / `→` 翻到同一个笔记的其它块 |

- **「第一个」= 文档顺序里第一个能打开的块**：八类区块混在一起按出现顺序算，空块（点了不会弹窗的块）不算，所以「第一个」永远是有内容可看的那一条。
- **笔记里一个可放大的块都没有时只提示**（「当前笔记里没有可放大的区块」），不会开一个空弹窗。
- **候选集与点放大图标完全一致**：同一个笔记里，命令打开的「总数 / 序号」与点图标打开时逐字相同；设置里单独关掉的区块类别（例如「放大代码块」）既没有图标、也不算这个命令的「第一个」。
- **不依赖放大图标**：把设置里的「启用放大图标」关掉（图标全部消失）之后命令照旧可用 —— 它扫的是**笔记文本**，不是屏幕上的图标。
- **只读**：命令不改动笔记、不改设置，只是打开弹窗。
- 之所以**没有**进编辑器右键菜单：它不需要选区，菜单里也没有对应的上下文（两个转换命令才需要选区）。**阅读视图**下不触发 —— 与两个转换命令同一套守卫（没有可编辑的编辑器就不执行）。

## 支持的标签

默认支持 `div` 与 `p`。可以在 **设置 → Text Popup → 支持的标签** 中修改（用逗号分隔，例如 `div, p, section`），改完立即生效，不需要改代码、也不需要重启插件。

判定规则：只有**块级原始 HTML** 才有放大图标。也就是说，只有你自己手写的 HTML 块会被识别；Markdown 语法（普通段落、标题、列表）生成的元素不会被误伤。这个列表**只作用于手写的 HTML 块**；代码块 / Callout / 数学块 / 图片 / 引用块 / 表格 / Canvas 由设置里各自的开关控制，与这里无关。

## 已知限制

- **只支持实时预览**：阅读视图没有「编辑这个模块」图标，也没有 `.embed-actions` 容器，注入无从下手；且原始 HTML 与 Markdown 生成的 `<p>` 在 DOM 上无法靠类名区分，因此 V1 不做阅读视图。**图片也一样**：阅读视图里的图片同样没有 `.embed-actions`。**引用块也一样**：它的图标由一个 CodeMirror 装饰器承载，而阅读视图根本没有 `EditorView` 可以挂。
- **参与 / 不参与候选的图片（真机实测）**：独立行、列表行（`- `）、正文里夹一张图的写法都支持（核心都给它们在 `.cm-line` 里建 `div.image-embed` + `.embed-actions`），**列表项里缩进 4 空格（或更多层嵌套）的图片同样支持**（V118 起）；**引用行**（`> ![x](p.png)`）里的图片由外层**引用块**覆盖（V114 起，此前它单独成条）、**Callout 内**的图片由外层 Callout 覆盖，两者都不单独成条；**表格单元格**、**行内 HTML 包裹**（`<span>![x](p.png)</span>`）、**缩进代码块里**、**行内代码**（`` `![x](p.png)` `` / `` `![[图.png]]` ``）的图片实测没有 `.image-embed` + `.embed-actions` 组合，一律不参与（行内代码里的图片在实时预览里只是一段文字 —— 反引号本身在 DOM 里是被隐藏的格式符，所以这是靠**笔记文本**判出来的，不是看 DOM）；**嵌入笔记**里的图片不注入图标（候选集来自外层笔记文本，点开也定位不到）。扩展名靠文本推断（图片扩展名表取自 `app.js`），外链（含 `://`）一律按图片处理，因此 `![](https://youtube.com/…)` 这种写法会多出一条无图标的条目（罕见，代价可接受）。**同一行里「代码里的图 + 后面的真图」时只认那张真图**（`![[a.png]]` 被反引号包着、`![[b.png]]` 在外面时，候选的正文是 `b.png`）—— 这一条是必需的：整行放弃会让真图上那个图标点开时定位不到候选、直接不弹窗。
- **行内代码的判定规则（真机实测，写在 `blocks.ts` 的 `inlineCodeRanges`）**：① 反引号串 = 连续 n 个 `` ` ``，找到**长度相同**的下一串就在那里闭合（同 CommonMark）；② 同一行找不到等长的那一串时，这一段**一直吃到行尾** —— 实时预览里**未闭合的反引号也当代码**（`` `abc ![[x]] `` 整段是 `span.cm-inline-code`，没有图标）；③ 前面有**奇数个**反斜杠的反引号被转义、不参与；④ 代码段**不跨行**（上一行的反引号不会影响这一行）。**已知不一致**：规则 ② 与**阅读视图**相反 —— `` `abc ![[x]] `` 在阅读视图里反引号是字面文本、图会显示出来。图标只存在于实时预览，所以候选集跟实时预览对齐，代价是这类写法在阅读视图里能看到图、却不进候选（与「引用块的懒惰续行」「外链图片多出一条」同性质的取舍）。
- **不支持移动端**：移动端没有悬停，Obsidian 内置的图片放大图标同样不含移动端，V1 跟随该行为。**引用块也一样**：装饰器在移动端直接返回空装饰集。
- **标题里的「总数」= 笔记里的可放大区块数，与滚动位置无关**：候选集来自**笔记文本**（不是当前屏幕上的图标），所以滚到任意位置、把光标停进任意块里、或分屏打开同一笔记，同一个笔记的总数始终一致。代价是**翻到视口外的块时编辑器不会跟着滚动**（弹窗是全屏模态，编辑器被遮住）；另外光标停在自己手写 HTML 块里时该块没有图标（这是 Obsidian 的既有行为），但它**仍在候选里**，可以从别的块用方向键翻到它。
- **缩进怎么算（V118 起按「相对容器」判，真机实测）**：哪些写法算「缩进代码块」、因而不进候选，判据不是「行首有几个空格」，而是**相对它所在容器**的缩进：`行首缩进列数 ≥ 容器的内容列 + 4`（Tab 按 4 列 tab stop 展开；列表项的容器内容列 = 标记缩进 + 标记宽度，`- ` 是 2、`1. ` 是 3、嵌套层更深）。所以同一个「4 空格」，在顶格是代码块，在 `- 父项` 里是正常嵌套、图片 / 围栏 / HTML 块都照样有图标 —— V118 之前这条守卫写成 `/^ {4,}/`（数行首空格），把列表项里合法的 4 空格图片一起拒了，导致那几处「有图标却点不开」。实测矩阵：

  | 写法 | 相对缩进 | 核心建 widget？ |
  | --- | --- | --- |
  | 段落续行 + 4 空格图 / HTML 块 | 4 | ✅ 有（段落延续，不是代码块）|
  | `- 父项` + 4 空格图 / HTML 块 / 围栏 | 2 | ✅ 有 |
  | `- 父项` + 3 空格 / 2 空格图、Tab 图 | 2–3 | ✅ 有 |
  | `1. 父项` + 4 空格图 | 1 | ✅ 有 |
  | 顶格 4 / 6 / 8 空格的 `$$` | 4–8 | ✅ 有（`$$` 是块级规则，能打断段落、也能在空行后另起块）|
  | 列表项内 4 / 6 / 10 空格的 `$$` | 2–8 | ✅ 有 |
  | 顶格 4 空格图 / 围栏、空行后 4 空格图 | 4 | ❌ 没有（缩进代码块）|
  | `- 父项` + 空行 + 6 空格图 / 围栏 / HTML 块 | 4 | ❌ 没有 |
  | `- 父项` + 空行 + 4 空格表 | 2 | ❌ 没有（**表格是唯一只认顶格的一类**，与容器无关）|
  | 上一行是缩进行的 `$$`（`    x` 换行 `    $$`）| 4 | ❌ 没有（已被在跑的缩进代码块吞掉）|

  两类例外说明：① **表格**不跟着这条规则走 —— 实测带任何前导空格的表头行在实时预览里都不是 `.cm-table-widget`（列表项内 2 / 4 空格都试过），所以它的守卫保持「必须顶格」；② **`$$` 与图片对空行的反应相反** —— `    x` + 空行 + `    $$` 实测是数学块（有 widget），同一个形状的图片则是代码块（没有 widget），因为 `$$` 是能另起块的块级规则、图片不是。返回给用户的后果只有一条：**图标有几个，候选就有几条**（有图标必能翻到，能翻到的必有图标）。
- **一处方向已知偏差（过度包含，V118 起意识到、接受现状）**：判定「本行是不是缩进代码块」时，上一条规则用「**上一行非空**」近似「上一行是段落」—— 于是 `# 标题` 紧跟 `    ![x](p.png)`（标题不是段落，其后的 4 空格其实**是**缩进代码块）会多出一条**幽灵候选**（能翻到、但编辑器里没有图标）。触发条件很窄（标题 / 分隔线等非段落块紧邻 4 空格图片行）。要精确就得引入「上一行是不是段落」的判断（要判 ATX / Setext / 围栏 / 列表段内外），代价明显大于收益，故接受并记录在此。
- **HTML 块按 CommonMark 的 HTML 块规则扫**：到第一个空行结束、`script` / `style` 一类标签不计入；缩进那一环与上一条同源 —— **相对容器 ≥4 列**的行视作缩进代码块、不计入，而不是「行首 4 个空格」。
- **候选块由笔记文本扫出，规则与编辑器渲染可能略有出入**：围栏代码块到闭围栏为止（闭围栏与开围栏**同容器**：允许的缩进上限是开围栏所在容器的内容列 + 3），Callout 与引用块到第一个非 `>` 行为止，`$$` 数学块到下一个 `$$` 为止，表格的判据与「表格转 HTML 命令」共用同一份实现（并额外要求表头行**顶格**）。未闭合的围栏 / `$$` 会一直扫到文末，`$$$` 这类多 `$` 写法以第一个 `$$` 为界 —— 都是**稳定**的多一个或少一个，不会抖动。
- **候选数会随笔记里的代码块、图片与引用块数量明显变多**：方向键要在八类区块之间依次翻。这是「候选集 = 本笔记全部可放大区块」这条原则的必然结果，不打算为了少翻几屏而把「只在屏幕上的块」重新算进来。
- **引用块的边界（真机实测）**：① 连续的 `>` 行**整段算一条**，引用里的标题 / 列表 / 围栏 / 嵌套（`> > `）都在这一条里，一个引用块只有一个图标；② **只有 `> ` 的空引用行**（连在引用段尾部）不产候选、也不挂图标（点开只会是一屏空白），但仍算进区间；③ **懒惰续行不算进区间**：`> a` 的下一行不写 `>` 时 Obsidian 仍把它画在引用条里，本实现按 `>` 前缀断句（与 Callout 同一取舍），弹窗里会少显示那一行；④ 引用行里的图片不单独成条（见上一条图片说明）；⑤ 引用块里的围栏不另算代码块、也不挂代码块 chip 的图标。
- **引用块图标的两个形态限制**：① 图标挂在**块的首行**（与核心把图标放在块右上角同理），因此长引用块滚动到首行离开视口时，图标随之离开；② 图标未悬停时是**透明但占位**的，盖住首行右上角最多约 28×24 px（实测胶囊尺寸），极长的首行文字末尾会被压住 —— 与核心对代码块 chip / 图片图标的做法一致。
- **性能**：引用块的图标要在文档每次变更时重算一次全文扫描（实测本库最大的笔记 829 行 / 19 545 字符，单次 0.295 ms）。若日后出现超大笔记，可按「变更行是否含 `>`」做增量跳过。
- **表格的边界（真机实测）**：① **表头行必须顶格** —— 带 1 / 2 / 3 个前导空格的表在实时预览里根本不生成表格 widget（只是普通文字，列表项延续时甚至是列表项里的文字），所以既不产候选也不挂图标；② **只有顶层的表格才有图标**：引用块里、Callout 里、裸 HTML 块里、列表项里的表格都不是顶层表格，由外层那一条候选覆盖（进弹窗仍能看到 —— 见「用法 → 表格」里的说明）；③ **结构化改动会重建 DOM**：插入 / 删除行列会让核心重建表格，图标先消失、150 ms 内被重扫补回，期间可能有一帧没有图标；④ 表格图标未悬停时**透明但占位**，盖住表头最后一格右上角约 28×24 px（实测胶囊尺寸）。
- **一处方向已知偏差（幽灵方向，与本轮表格支持无关但会被表格放大）**：`matchHtmlBlock` 按 CommonMark 停在第一个空行，而实测实时预览会把整个 `<div>…</div>`（**中间含空行**）当成**一个** HTML 块。于是「HTML 块 → 空行 → 表格」这种写法里，表格文本会产出一条候选，而编辑器里并没有 `.cm-table-widget`（= 能翻到但没图标的幽灵）。它与图片 / 引用块的同类偏差同源，建议单开一轮修 `matchHtmlBlock` 的边界，本轮不加表格专属补丁。
- **内部类名依赖（全是非公开 API，已对照 `obsidian.asar` 的 `app.js` / `app.css` 原文）**：`.cm-embed-block` 及其分类用的 `.cm-html-embed` / `.cm-preview-code-block` / `.cm-callout` / `.math-block` / `.cm-table-widget`（表格容器**也**带 `.cm-embed-block`）、表格的注入锚点 `.table-wrapper`、图标容器 `.embed-actions`（**图片版 / 引用块版 / 表格版是同一套**，仍然插首位）、普通代码块右上角的 `.code-block-flair`、图片嵌入的容器 `.image-embed`、引用行的类名 `HyperMD-quote`（引用块**要**据此挂图标，与代码块 chip「跳过引用行的围栏」的判断相反），以及「`.cm-line` 是 `position: relative`」这条定位前提（核心写在 `app.css` 的 `.markdown-source-view.mod-cm6 .cm-line` 上，核心自己的 `.code-block-flair` 也靠它）。另外表格的悬停显形依赖核心 `app.css` 里那条把表格排除在外的显隐规则（`.cm-embed-block:not(.cm-table-widget, .cm-lang-base):hover .embed-actions`）—— 我们补的规则正是为它而写。Obsidian 升级后若图标不出现，集中修改 `src/scanner/inject.ts` 的 `injectAction` / `injectFlairAction` / `injectImageAction` / `injectTableAction` 与 `src/scanner/shared.ts` 的选择器（`IMAGE_SELECTOR` / `TABLE_WIDGET_CLASS` / `TABLE_ACTIONS_CLASS`）即可；引用块图标不出现则先看 `src/scanner/quote.ts` 的 `buildDecorations` 与 `styles.css` 里那条显隐规则。
- **代码块有两种形态，图标位置因此不同**：语言被 `mermaid` / `query` / `base` 等 post-processor 接管时，核心把代码块建成 widget，图标在「编辑这个模块」`</>` 左侧；普通语言（如 `typescript`）核心**不建 widget**，只把代码留成源码行，并在开围栏行末尾挂一个 `.code-block-flair` chip 当右上角的语言名 / 点击复制，图标就嵌在这个 chip 里。**这也是为什么代码块的图标是常显的**（chip 本身常显，核心没给它做悬停显隐），而 Callout / 数学块 / 图片 / 引用块四类要悬停才出现。
- **引用块里的围栏不加代码块图标**：行首是 `>` 的围栏行（`>` 后面接三反引号）在扫描器里不算代码块区间（行首是 `>`），所以那里既不是代码块候选、也不挂代码块 chip 的图标 —— 避免出现「点开却翻出别的区块」。同理，Callout 内部的代码块由 Callout 自己渲染，只按外层 Callout 计一条。这两处的整段内容都由外层那一条覆盖，因此整段只有**外层那一个**放大图标（V114 起引用块也有了自己的图标）。
- **围栏语言为 `base` 的代码块会按代码块处理**：核心也用 `.cm-preview-code-block` 建它的容器，并且 CSS 给它的控制图标条设了常显，所以它同样会有放大图标；这也是「有控制图标的区块才加放大图标」这条判据的自然结果。
- **代码块的渲染走全局 post-processor**：`mermaid` / `dataview` / `base` 这类由其它处理器接管的语言，在弹窗里也走同一套处理器（例如 `mermaid` 会渲染成图）；需要文件 / 仓库上下文的处理器能否出结果取决于其自身实现，渲染失败时弹窗会自动回退为纯文本。
- **HTML 块内的 Markdown 由本插件解析**：Obsidian 本身不解析 HTML 块内的 Markdown，弹窗里的解析由本插件用 `MarkdownRenderer` 完成，因此弹窗内与编辑器内的呈现可能不一致（编辑器里 `**粗体**` 仍是原文，弹窗里会渲染成粗体）。若想看到原文，关闭设置里的「渲染 HTML 与 Markdown」。
- **命令的边界**：`Popup Selected Text` 会拒绝缩进 4 空格以上的选区（会被当成代码块）、位于代码块 / 标注 / 数学块内的选区（会被转成字面文本）、以及已经含有点击块的选区（先用 `Unpopup Selected Text` 还原）；这些情况只弹提示、一个字节都不改。**引用行不在拒绝之列**：选区里含 `> 引用` 照常转换（`>` 会作为块内原文留下，弹窗重新渲染时正好显示成真正的引用），同理 V113 起图片行也照常。`Unpopup Selected Text` 一次只处理一个块，块内手写的 `<b>` `<i>` `<s>` 会归一成 `**` / `*` / `~~`（反向对照表的既定写法）。另外，已生成的块只有在外层标签**仍留在「支持的标签」里**时才有放大图标、才能被 `Unpopup` 认出来：把 `p` 从列表里删掉后，之前生成的 `<p>` 块会同时失去图标与反向还原能力，加回来即恢复。
- **右键菜单入口以桌面端为准**：两个命令本身在移动端可用（命令面板 / 移动工具栏），但部分移动端路径下核心不触发 `editor-menu`，右键菜单不一定出现。
- **列表与表格转换的已知限制**：① 分隔线（`- - -` / `* * *` / `---`）与「标记后没有空白」的写法（`-test`、`*斜体*`）按原文保留、不按列表转换；② 首行缩进 4 空格以上的选区仍被既有守卫整体拒绝，所以「一段本来就缩进 4 空格的子列表」也照样会被拒；③ 关闭设置里的「渲染 HTML 与 Markdown」后，列表退化成纯文本（`innerText` 不含项目符号与复选框），复选框在 HTML 块里**点不动**（带 `disabled`）。表格侧还有：④ **列表项内部的表格**（`- a` 下面缩进的表格）不转换 —— 既有列表处理本就不认「项里的块级内容」，保持一致；⑤ 表格的**单元格里不能有换行**（`<br>`、嵌套列表 / 表格），HTML 侧遇到这类结构整段保留、不还原；⑥ 合并单元格（`colspan` / `rowspan`）在 Markdown 表格里表达不了，反向时整段保留；⑦ 关闭「渲染 HTML 与 Markdown」时，表格的纯文本形态是「单元格文字被换行 / 制表符平铺」（走 `innerText`，既有行为）。
- **标题转换的已知限制**：① **Setext 标题**（`S` + `===` / `---`）不转也不还原 —— 往返必然变形，且 `===` / `---` 与分隔线、表格分隔行共享字符；`S` + `===` 在弹窗里落在一个段落里（`===` 是字面文本），所以不转的代价只是形态没升级、内容不会被吞。② **列表项里的标题**（`- # T`）不转换，`#` 保持字面 —— 既有列表实现只认「项内容 = 一行行内文本」，与「表格放在列表项里」同一条边界。③ `> #### T` 这类**引用行里的标题**留给原文（弹窗里 `>` 会被序列化成 `&gt;`，本来就不会变成引用）。④ 标题的**尾部闭合串不保留、分隔空白与缩进会被归一**（见上面的归一化清单），所以「本来就是标题的文本」过一次转换后不是逐字节相同。⑤ 选区中间夹着**未闭合的代码围栏**（```）时后文会被吃进代码块 —— 既有观察，与标题无关，不在本次范围。⑥ 表格「必须起一个块」这条前置条件**只放宽了「上一行是 ATX 标题」**一种；分隔行之后、列表行 / 引用行之后仍然不判表格（与既有「宁可漏判」一致）。
- **手写的畸形 HTML 不会被修复**：`Unpopup Selected Text` 找不到外层标签的闭合标签时直接拒绝，不猜、不改。
- **块内已嵌入的 `![[笔记]]` 嵌入块**：这类内容在编辑器里已被核心处理成交互式嵌入节点，回灌渲染后只保留外观、失去交互（不会重新加载被嵌入的内容）。属于已知限制。
- **Canvas 的边界（真机实测，V119 起）**：① 弹窗里的画布是**自研只读快照**，**不追求与核心画布像素级一致** —— 字体层级、核心的 `--zoom-multiplier` 那一套、组的背景图、边的曲率细节都不做；② **没有任何写回路径**：拖拽节点 / 双击文字都不会改动 `.canvas` 文件，也没有选中、编辑、缩放画布本体、加卡片、右键菜单这些能力（弹窗的定位是只读浏览）；③ 画布**解析不到文件**（被删 / 改名 / 找不到）时既不挂图标也不产候选（不会有点不开的死图标），JSON 坏掉或一个节点都画不出来时回退成**文件名纯文本**、不是空白屏；④ 快照**只缩不放**（小画布按原尺寸居中），节点文字**固定 16px** 不跟随弹窗字号（节点盒宽高来自画布 JSON，字号一变文字就溢出被裁）；⑤ 节点里的 `[[链接]]` 点击会**导航当前窗口**（与核心画布一致），弹窗本身不关；⑥ 组背景图、画布内嵌画布不做；⑦ **Callout / 引用块内**嵌的画布、以及**嵌入笔记**里的画布仍由外层那一条覆盖（弹窗里出现的是核心的缩略图），与图片那两处同一条边界；⑧ 笔记卡片的「缩小至标题 / 块」**只读不回显**：弹窗里不提供「缩小至…」入口（那要么写进画布文件、要么往笔记里写块 id，与快照零写回冲突），想改就去画布里右键改，弹窗跟着变；非法 subpath（不以 `#` 开头，只可能来自手改的 `.canvas`）**忽略、退回整篇**，不会渲染成一串未解析文字。
- **Canvas 与普通图片在候选层就是两类**：`![[x.canvas]]` 归 `canvas`、`![[x.excalidraw]]` 仍归 `image`（它走「同名 PNG/SVG 图片回退」），所以「放大 Canvas」与「放大图片」是两个独立开关 —— 关掉前者不影响图片与 Excalidraw。
- **图片既是「区块内容」也可以是「区块本身」**：块内只有一张图片时（例如手写 HTML 块里只放了一张图），本插件弹的仍是文字弹窗、内容就是那张图，而不是图片 lightbox（lightbox 由 Obsidian 原生的「放大」图标提供）；而图片**作为独立区块**时（见「用法 → 图片」）本插件给它在原生「放大」图标左侧加了一个自己的图标，点它也走本插件的弹窗。
- **弹窗里的图片不受「字号 / 缩放」影响**：图片不吃 `font-size`，所以底部控制条的缩放对图片是无效的（对文字与 mermaid 图生效）。图片按 `max-width: 100%` 收缩，不会撑破内容区；需要更大就看原生查看器。
- 富文本渲染是**异步**的：内容极大的块打开时会先短暂显示空白容器再填充；数学块首次打开还要先动态加载 MathJax，可能多等一下（弹窗会等到排版完成，不会显示错误内容）。
- 弹窗里的**缩放是按比例作用于字号**的（50%–400%），这样内容会自然重排，不会被裁切。「恢复默认」会把字号还原成设置里的值、缩放还原成 100%。
- 弹窗尺寸固定为**应用窗口的 100%×100%**，目前不提供半屏 / 自定义尺寸的选项。
- **方向键只在点击时的那个窗格内切换**：分屏并排打开两个都含可放大区块的笔记时，在哪个窗格点开图标就只在那个窗格内切换，不会跨到另一个窗格；笔记里只有一个可放大区块时，方向键不产生任何变化（标题栏也不带序号）。
- **方向键只占用 `←` / `→`**：`↑` / `↓` 仍是滚动正文，内容长的块不会被抢走键盘滚动。也不提供控制条上的「上一个 / 下一个」按钮。
- 弹窗打开期间若在别处编辑同一个笔记，弹窗里仍是**打开那一刻**的候选与正文（打开时取一次快照）；关闭后重新打开即为最新内容。某一条为空时不会切到空白屏。

### 实现要点

**设置页是声明式的，取值 / 存值 / 副作用各只有一处。**

- 设置页由 `TextPopupSettingTab.getSettingDefinitions()` 返回 3 组 17 条定义，核心（1.13+）据此渲染，并把 `name` / `desc` 编进**设置搜索**索引 —— 这正是 `manifest.json` 的 `minAppVersion` 必须 ≥ `1.13.0` 的原因（`display()` 已标 `@deprecated`，不再保留第二套命令式设置页）。
- 控件的读 / 写统一走 `settings.ts` 导出的纯函数 `readSettingValue` / `writeSettingValue`；「改完这个键要刷新什么」只有 `settingSideEffects` 一张表：`refreshActions` → `refreshTextPopupActions`、`quoteActions` → `notifyQuoteActionsChanged`、`rebuildDefinitions` → `this.update()`。**改字号 / 改颜色不触发任何扫描**（见上文引用块那条自激教训），由单测钉住。`writeSettingValue` 会返回「值有没有真的变」，值没变就不保存、不刷新。
- 颜色两行用**虚拟键**（`popupBackgroundFollowTheme` / `popupTextFollowTheme`）表达「跟随主题」，`data.json` 里依旧只有 `popupBackgroundColor` / `popupTextColor` 两个字段、空串仍表示跟随主题。不能直接把空串喂给色块控件：`<input type="color">` 表示不了空值，浏览器会把它显示成 `#000000`。
- 「支持的标签」改完要顺手把两个包裹标签拉回合法值（**先多行、后单行**，回落链依赖这个顺序），并重建定义让两个下拉的选项跟着变。重建时核心会**跳过焦点所在的那一行**，所以在输入框里打字不会丢焦点 —— 这也是原来那段手写下拉同步可以整段删掉的原因。

**候选集是同一套，注入点有五处。**

- **widget 类区块**（块级原始 HTML、Callout、数学块，以及被 `mermaid` / `base` 等 post-processor 接管的代码块）：容器都带 `.cm-embed-block`，都在容器内建 `.embed-actions` 放控制图标（可与 `obsidian.asar` 的 `app.js` 原文对照：`createEl("div", "cm-html-embed cm-embed-block")`、`createDiv("cm-preview-code-block cm-embed-block …")`、`createDiv("cm-embed-block cm-callout")`、`toggleClass("math-block" / "cm-embed-block")`）。放大图标插进 `.embed-actions` 首位，因此自动获得「悬停显示、右上角定位、RTL 镜像」等核心行为，不需要自己写定位与显隐样式。
- **普通围栏代码块**（语言不是 `mermaid` / `query` / 有 post-processor 的）：`P3.canRenderLang(lang)` 为假，核心**不建 widget**，只把代码留成源码行（`HyperMD-codeblock`），并在开围栏行末尾挂一个 widget `E3` —— 它的 `toDOM` 就是 `createSpan({ cls: "code-block-flair" })`，即右上角的语言名 / 点击复制 chip。它没有 `.embed-actions`，所以放大图标作为 chip 的**子节点**嵌进去（`styles.css` 的 `.text-popup-flair-action` 负责摆成行内）。
  为什么嵌进 chip 而不是当兄弟节点插到 `.cm-line` 上：CM6 的 DOMObserver 会**忽略 widget 内部的** DOM 变更（`readMutation` 里命中 widget tile 直接返回 null），而往 `.cm-line` 里塞一个它不认识的节点会被算成一次 DOM 变更、把整行标脏重渲染 —— 那会反复把按钮冲掉。
- **图片嵌入**：容器**不是** `.cm-embed-block`（这正是最初的 `.cm-embed-block` 选择器完全扫不到图片的原因），而是核心给图片 widget 自己建的 `div.image-embed`。它内部的 `.embed-actions` 与 widget 类区块是同一套（`addActions` → `addAction` → `this.actionsEl ||= e.createDiv("embed-actions")`），所以放大图标照旧插首位、插在原生「放大」（`lucide-zoom-in`）左侧，胶囊皮肤 / 悬停显隐 / RTL 镜像全部白拿，**不需要新增任何 CSS**。注入前有三条守卫：没有 `.embed-actions` 的图片（Callout 内、行内 HTML 里的 `span.image-embed`）天然跳过，嵌入笔记（`.markdown-embed`）里的图片也跳过，**引用行**（`.cm-line.HyperMD-quote`）里的图片同样跳过（V114 起由外层引用块覆盖）—— 与扫描器「这几类不产候选」的判断保持一致。
- **表格**（`injectTableAction`）：唯一一处**容器也要自己建**的注入点。表格 widget 的容器 `.cm-table-widget` 带 `.cm-embed-block`（所以按 `.cm-embed-block` 分类的遍历本来就扫得到它），但核心的 `addEditButton` 只有 5 个调用点（嵌入笔记 / 两种代码块 / 数学块 / HTML 块），**表格不在其中** —— 它没有现成的 `.embed-actions`。所以本插件在 `.table-wrapper` 里自己建一个 `text-popup-table-actions embed-actions` 再插按钮：`embed-actions` 用来白拿核心的定位与皮肤，`text-popup-table-actions` 用来**认领**这个容器（摘的时候要连容器一起摘，且绝不能误删核心建的 `.embed-actions`）。锚点选 `.table-wrapper`（表格本体）而不是 widget 容器：后者常被拉满行宽（实测同一张表 732px vs 347px），锚在它上面按钮会飘到编辑区右缘。给表格按钮额外补了一条 **`mousedown` 守卫**（`preventDefault` + `stopPropagation`）：表格式块内部有真实可编辑的单元格，实测只拦 `click` 时点击按钮会被顺手挪动光标。核心只在 `.cm-embed-block:hover` / `.image-embed:hover` 里显形，而表格被核心那条规则用 `:not(.cm-table-widget, …)` **显式排除**，所以 `styles.css` 里补了一条 `.cm-table-widget:hover .embed-actions { opacity: 1 }`。
- **引用块**（`src/scanner/quote.ts`）：**唯一一处不是 DOM 注入的注入点**。引用块在实时预览里没有容器，它只是一串 `.cm-line.HyperMD-quote`（实测普通引用行上一条 `.cm-embed-block` 都没有），而往 `.cm-line` 里插的节点会被 CM6 的 DOMObserver 当成文档变更、整行重渲染时冲掉（实测 2 秒内消失）—— 与上一条「代码块 chip 必须嵌在 widget 内部」同因。所以这里走核心自己在普通行上用的那条路（对照核心的 `.code-block-flair`：它就是 `.cm-line.HyperMD-codeblock-begin` 里的一个绝对定位元素）：由一个 CM6 装饰器（`ViewPlugin` + `Decoration.widget`）承载按钮，DOM 由 CM6 托管，不会被冲掉，定位也白拿。DOM 形状仍是核心那套 `div.embed-actions > div.embed-action`，因此皮肤全部复用；核心只在 `.cm-embed-block:hover` / `.image-embed:hover` 里显形，引用块两种都不是，所以 `styles.css` 里补了一条显隐规则（悬停首行 + 由委托监听写的 `data-text-popup-hover`）。设置变更靠 `StateEffect` 重建装饰集（`notifyQuoteActionsChanged`），**且只能由设置页触发** —— 塞进 `refreshTextPopupActions` 的观察者路径会让 dispatch → 改 DOM → 观察者 → dispatch 自激。

扫描是**一次 `.cm-embed-block` 遍历 + 类名分类**（`classifyBlock`）：块级原始 HTML / 代码块 widget / Callout / 数学块 / **表格**共用这一次遍历，各自按类别分流（表格走 `injectTableAction`，其余走 `injectAction`）；不带这几类类名的核心区块仍直接跳过。另有 `.code-block-flair` 与 `.cm-content .image-embed` 两次遍历，前者只吃「放大代码块」这一个开关，后者只吃「放大图片」。引用块不在这三次遍历里 —— 它的图标随装饰器自动重算，`removeAllActions` 也要跳过它（widget 的 DOM 归 CM6 管，删了不会自己长回来），但要顺手清掉表格那个**本插件认领的**空容器。

这些都依赖 Obsidian 的内部类名（非公开 API），升级后若图标不出现，集中修改 `src/scanner/inject.ts` 的 `injectAction` / `injectFlairAction` / `injectImageAction` / `injectTableAction` 与 `src/scanner/shared.ts` 的选择器即可；引用块见 `src/scanner/quote.ts`。

富文本渲染走**公开 API** `MarkdownRenderer.render(app, markdown, el, sourcePath, component)`：

- 传入的 markdown 分两路：手写 HTML 块传「去掉外层容器标签后的 `innerHTML`」（若直接传 `outerHTML`，字符串以 `<div>` 开头会被按 CommonMark 的 HTML block 规则整段吞掉，块内 Markdown 不会解析）；代码块 / Callout / 数学块 / 引用块 / **表格**直接传**区间原文**（含围栏 / `> ` 前缀 / `$$` / `|` 网格），由 `MarkdownRenderer` 渲染成对应的原生形态 —— 引用块的原文正好渲染成一个带引用条的 `<blockquote>`，表格原文以 `|` 开头、照样被认成表格（不像 `<div>` 开头那样被 HTML block 规则吞掉），这是需求「模仿 Obsidian 显示」最省力的实现。
- 必须传一个真实的 `Component`（弹窗持有的 `component`），在 `onOpen` 里 `load()`、`onClose` 里 `unload()`；否则核心会打印 `is not passing Component` 告警，且嵌入内容的事件监听会泄漏。
- `sourcePath` 必须传**笔记完整路径**（`TFile.path`），`[[wikilink]]` 与 `![[图片]]` 才能正确解析。
- 内容容器加 `markdown-rendered` 类即可复用核心的标题 / 列表 / 引用 / 表格 / 代码块样式，不需要自己写 Markdown CSS。
- 输入前会按最小缩进整体左移（`dedent`）：Markdown 中 4 个及以上前导空格会被当成代码块，不去缩进会把块内文字误渲染成代码块。
- 渲染为空或抛错时自动回退为纯文本，弹窗不会空白。

方向键切换的**候选集来自笔记文本**，不是 DOM：

- 弹窗的数据入口从「一条内容」改为 `TextPopupSource`（`size` / `sourceName` / `sourcePath` / `read(index)` / `dispose()`），由 `scanner/session.ts` 实现，弹窗只按索引惰性读取，不认识 DOM。
- 候选集由 `blocks.ts` 的 `scanTextBlocks(editor.getValue())` 扫出：单趟扫描、命中即吃掉整段区间，因此区间天然不重叠、**外层优先**（Callout 里嵌的代码块不会另算一条，否则会出现「能翻到、但永远没有图标」的幽灵条目）。HTML 块的标签表与排除表都从 `obsidian.asar` 抄来，规则与核心对齐。**为什么不用 DOM**：Live Preview 只渲染视口附近的块，滚出视口的块连按钮都没有；以 DOM 为准会让「能翻到几条」随滚动位置、光标位置、分屏状态变化（这就是「有时 2 个、有时 4 个、有时 5 个」的根因）。数量必须是**笔记的属性**，不能是屏幕的属性。
- 八类的**纯文本回退**分别由 `extractFencedBody` / `extractCalloutBody` / `extractMathBody` / `extractImageBody` / `extractQuoteBody` / `extractTableBody` / `extractCanvasBody` 得到（代码正文 / 去掉 `> ` 的文字 / TeX 源码 / alt 或文件名 / 去掉 `> ` 前缀的引用文字 / 去掉首尾空行的表格原文 / 画布文件名），只有手写 HTML 块才需要离屏渲染；空块不进候选，所以按方向键不会切到一屏空白。表格是唯一**不去壳**的一类（`|` 网格本身就是内容，剥它就得重排对齐列宽），只有「表头每格都空且没有数据行」的纯空表才返回空串、让候选被丢掉。图片 / Canvas 区的 `raw` 存的是**命中的那段图片语法**而不是整行：引用行 / 列表行的 `> ` `- ` 前缀喂给 `MarkdownRenderer` 会多渲染出一层引用块 / 列表项；引用块的 `raw` 则相反，**保留**每行的 `> ` 前缀，正好渲染成 `<blockquote>`。
- 图片的**行级排除**共四条，都判在 `blocks.ts` 的 `matchImageBlock` 里（缩进 / 表格 / 行内 HTML / 行内代码），理由是同一个：**实测这四种写法核心都不建 `.image-embed`**，放进候选就是「能翻到、但永远没有图标」的幽灵条目。其中缩进那条自 V118 起按**相对容器**判（`isIndentedCode`：相对所在列表项的内容列满 4 列才算代码块），围栏 / `$$` / HTML 块三条守卫同轮一起改（`$$` 那类几乎不吃缩进，只排除「已被在跑的缩进代码块吞掉」的行），表格那条保持不变。行内代码的区间由 `inlineCodeRanges` 从**笔记文本**算出（四条实测规则，见「已知限制」），命中的图片用 `firstHitOutsideCode` **跳过**而不是「整行放弃」—— 同一行里「代码里的图 + 后面的真图」时，后面那张真图必须仍是候选。
- 候选的正文用**离屏渲染**取得：手写 HTML 的每个区间交给公开 API `sanitizeHTMLToDom`（核心 widget 自己用的就是这个函数），渲染进一个 `position: fixed; left: -10000px` 的离屏宿主，再跑原来的 `findSupportedElement` / `extractText` / `extractRichSource`。隐藏方式不能用 `display: none`：`extractText` 依赖 `innerText`，元素不参与布局时 `innerText` 会退化成 `textContent`，`<br>` 的换行会丢。另外六类是纯字符串处理，不需要离屏宿主。
- 打开时**算一次、取一次快照**：`size` 与 `read(index)` 都读同一份候选，弹窗打开期间不再重采，所以标题里的「总数 / 序号」与正文永远同源（旧实现每次切换都重采 DOM，点击后核心把光标移进块并滚动，会让数字在打开后继续变，点最后一个块还会因为越界而弹空白）。离屏宿主在 `onClose` 里通过 `source.dispose()` 移除。
- 「点开的是第几个」用 `Editor.cm`（核心内部入口，`obsidian.d.ts` 未暴露）上的 CM6 `posAtDOM` 把块容器映射回行号，再落到区间上；失败时按内容相等兜底，再不行回第 1 条。代码块 chip / 图片 / 引用块这三处的按钮不在 `.cm-embed-block` 里，退回所在行（`.cm-line`）精确匹配区间起始行，对不上就**不开弹窗**（宁可不开，也不翻出别的块）。表格的按钮在 `.cm-table-widget` 里（它带 `.cm-embed-block`），走的是「块容器 → 行号 → 落进区间」那条主路径。**这是本插件唯一新增的内部入口依赖**，与已有的 `.cm-html-embed` 类名依赖同级；只在 `locateStartIndex` 一处使用，包在 `try/catch` 里。
- 引用块的**图标侧与候选侧同源**：两侧都用同一个 `scanTextBlocks` 与 `isKindEnabled`，图标侧额外过滤「正文为空」的引用块（`readTextBody` 返回空串），与候选侧 `createCandidate` 的判据一致 —— 「有图标必有一条候选」是本仓库的硬约束，不满足就会出现「有图标、点开没反应」的幽灵。
- 按钮带核心约定的 `interactive-child` 类，并在 click 里 `preventDefault` + `stopPropagation`：核心在 widget 容器上挂了「点击即进入块内编辑」的延迟处理（先判 `defaultPrevented`，10ms 后才执行），拦住它就不会出现「光标跳进块、编辑器滚动、刚点的图标消失」。
- 键位注册在 `Modal` 自带的 `this.scope` 上（`open()` 时核心已把它压进键盘栈，`close()` 时自动弹出，不会漏监听）。handler **返回 `false`** 才会让核心 `preventDefault` + `stopPropagation`，方向键不会冒泡给编辑器；`modifiers` 传 `null` 表示不限修饰键，与内置图片 lightbox 行为对齐。
- `MarkdownRenderer.render` 是 **append 语义且异步**：连按方向键时两次渲染会交错写进同一个容器导致内容串台。因此每次切换都渲染到**独立的新容器**，并配合自增 `renderToken` 丢弃过期渲染；子组件一律用 `Component.addChild` / `removeChild` 管理（它们会随父组件自动 load / unload），不手写 `load()` / `unload()`。
- Alt+Click 的缩放过渡**不用 CSS `transition`**，而是 `requestAnimationFrame` 逐帧写 scale 变量与滚动量。屏幕坐标 = 元素原点 − 滚动量 + scale × 元素本地坐标，`transition` 只管得住 `transform` 那一项，滚动还得靠另一条时间线去追 —— 两条时间线一定会错开，中途就能看到锚点脱轨。「每帧先写 scale 变量、再写滚动量」的顺序也不能反：滚动赋值会被夹在由 scale 决定的滚动上限上，反过来会被夹在上一帧的上限上。整个过渡（`VIEW_ZOOM_DURATION` / `easeOutCubic` / `zoomTweenFrame`）是可打断的：切换条目、恢复默认、开始拖拽、关窗都会先 `cancelViewZoom()`。
